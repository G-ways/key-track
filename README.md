# Key Management System

A small system for tracking physical key sign-in/sign-out via a QR code that
rotates every 24 hours.

## How it works

- One QR code is displayed on a screen/tablet near the keys (`/` route,
  `Display.jsx`). It's generated by the server the first time it's requested
  each day and expires exactly `QR_LIFETIME_HOURS` (default 24) later.
- Someone scans it with their phone, which opens `/scan?token=...`. The page
  checks the token is still valid, then asks for their **name**, the
  **key/location**, and whether they're **signing in or out**. Date and time
  are captured automatically (server-side, at the moment of submission).
- `/admin/logs` is a bare-bones table to review a day's entries. There's no
  authentication on it yet — see "Before you deploy this" below.

## Project layout

```
server/   Express + MongoDB API
client/   React (Vite) frontend
```

## Running it locally

### 1. Backend

```bash
cd server
cp .env.example .env   # edit MONGO_URI / FRONTEND_URL if needed
npm install
npm run dev
```

This starts the API on `http://localhost:4000`.

### 2. Frontend

```bash
cd client
npm install
npm run dev
```

This starts the app on `http://localhost:5173`.

- Wall display: `http://localhost:5173/`
- Scan/sign form: opened automatically when someone scans the QR code
- Admin log: `http://localhost:5173/admin/logs`

### 3. Add at least one key/location

The scan form's dropdown is empty until you add locations. Either use
MongoDB Compass/shell, or hit the API directly:

```bash
curl -X POST http://localhost:4000/api/locations \
  -H "Content-Type: application/json" \
  -d '{"name": "Room 101"}'
```

## How the 24-hour rotation works

`server/src/utils/token.js` keys one token document per calendar day
(`dateKey`, e.g. `2026-09-10`) with an `expiresAt` timestamp 24 hours after
first creation. The display page polls `/api/qr/today` once a minute, so it
picks up the new code shortly after the old one expires — no cron job
required, though you could add one (e.g. with `node-cron`) to pre-generate
the next day's token exactly at midnight if you want zero gap.

## Before you deploy this for real

This is a working scaffold, not a production-hardened app. Before relying on
it:

- **Add authentication** to `POST /api/locations` and `/admin/logs` (currently
  open to anyone who finds the URL).
- **Rate-limit** `/api/logs` so the form can't be spammed.
- **Decide on timezone handling** — `todayKey()` uses the server's local time;
  pin the server's `TZ` environment variable if it might run somewhere other
  than where the key station is.
- Consider whether you want the system to **block** a sign-out from someone
  who never signed in (or vice versa) — right now it logs whatever the person
  selects, since sign-in/out is chosen manually rather than inferred.
